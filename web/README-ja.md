# Character Relationship Chart — Web版

[English](README.md)

第5段階完了版です（2026-09-28 JST）。自動試験と、利用者の実機での直接保存・再読込・外部変更時の保存停止を確認しました。配布ZIPをすべて展開し、JavaScript・FileReader・ResizeObserver・dialog・Blobのダウンロードに対応したデスクトップブラウザで `index.html` を開きます。同梱ファイルは一緒に置いてください。完成した配布物の利用にVS Code、Node.js、Webサーバー、インターネット接続は不要です。

起動時にはサンプルが表示されます。**設定を開く**でUTF-8の `.jsonc` または `.json` を1つ選択するか、画面へドロップしてください。対応する表示データを同時に選択・ドロップすることもできます。後から読み込む場合は **表示データを開く** を使います。表示データの名前は設定ファイルの完全な名前に `.view.json` を付けたものです。例: `cast.jsonc` と `cast.jsonc.view.json`。同じフォルダーのファイルを自動で読み取ることはありません。外部で編集した内容は同じファイルをもう一度選択して読み直します。

**編集**で人物・グループ・関係・全体設定を、VS Code版と同じGUIで編集できます。**反映**を押すとフォームの内容を相関図とページ内のJSONCへ適用します。編集画面を閉じて **設定をダウンロード** を押すと、反映済みの内容を、元の `.jsonc` / `.json` のファイル名を基本とするUTF-8のファイルとして取得できます。ブラウザが名前を調整したり、保存先を尋ねたりする場合があります。開始後はブラウザの保存先を確認してください。開始だけでは保存完了を判定できません。以後はダウンロードしたファイルを開いて利用します。未反映のフォーム入力をダウンロードへ暗黙に含めることはありません。

編集処理は共通コアを使用します。複数グループ所属、人物・グループのID変更時の参照追従、人物削除時の接続関係の削除、グループ削除時の所属解除は既存版と同じです。全体設定のタイトル・説明は追加・変更・空欄による削除ができます。変更対象外のコメント、改行、インデントは可能な範囲で保持します。項目の追加・削除では隣接範囲が整形される場合がありますが、ファイル全体をJSONへ変換し直すことはありません。`.json` 入力も拡張子を維持し、VS Code版と同じJSONC互換の内容を扱います。

検索、人物・関係のクリックによる詳細表示、ノードとキャンバスのドラッグ、拡大縮小、配置方式の変更、図だけ表示を利用できます。ノードのドラッグでは詳細を開かず、全エッジラベルはエッジ線より前面に表示します。人物IDを変更しても一時的なドラッグ位置と選択を引き継ぎます。配置変更は一時的で、画面を閉じる・再読込する・別の設定を開くと失われます。設定を開くと以前の選択・検索・配置をリセットし、対応する表示データがあればその配置を復元します。

不正なデータ、読込エラー、不正な編集では、直前の有効な図とフォーム入力を保持します。設定と表示データを同時に選んだ場合は、両方が有効なときだけ切り替えます。複数の設定、対応しない表示ファイル名、大きすぎる入力は拒否します。ダウンロードに失敗してもページ内の編集内容は残り、再試行できます。反映済みの編集や開いているフォームに入力がある場合、別設定への切替前に破棄確認を行います。ダウンロード後もブラウザの保存完了を判定できないため、この確認は残ります。編集がある状態でページを閉じる・再読込するときも警告を要求しますが、ブラウザによって表示されない場合があります。離れる前に直接保存の完了、またはダウンロード先を確認してください。

`.view.json` の保存・ダウンロード、SVGダウンロード、Web版のUndo/Redo、常時のファイル監視、localStorage・IndexedDBへの永続保存はありません。直接保存またはダウンロードまではページのメモリー上だけで扱い、内容を外部へ送信しません。外部リソース・利用状況の収集・ネットワーク要求はなく、CSPでも接続を禁止します。ページの再読込では再びサンプルが開きます。

## 元ファイルへ保存する（対応環境のみ）

- **直接保存用に開く** で元の `.jsonc` / `.json` を選びます。通常の **設定を開く**、ドロップ、サンプルでは書込ハンドルを保持せず、ダウンロードを使います。表示データは後から **表示データを開く** で読み込めます。
- GUIで **反映** し、編集画面を閉じて **保存** を押します。書込権限の要求が表示されたら、保存先を確認して許可します。保存対象はその時点の反映済みJSONCです。未反映フォームを自動適用せず、自動保存もしません。
- **保存** は選択した元ファイルを更新します。**設定をダウンロード** は反映済み内容のコピーを出力します。保存先を選び直す「名前を付けて保存」はありません。
- 元ファイルを読込時（以後は最後に確認できた保存時）のバイト列と比較します。コメント・空白・BOMの違いも競合です。変更を検出したら上書きを停止し、図・入力・編集を残します。ダウンロードで退避してから元ファイルを確認し、必要な設定を開き直してください。自動マージ・自動採用はしません。
- 権限拒否・読込失敗・書込失敗でも編集内容を保持します。保存結果が不明な場合は直接保存を停止し、再送しません。ダウンロードで退避し、元ファイルの内容を確認してください。
- 書込完了後に元ファイルを再読込して内容を照合します。保存した内容と現在の反映済み内容が一致した場合だけ設定の未保存状態を解除します。保存中の追加編集や未反映のフォームは保持し、ダウンロードだけでは未保存状態を解除しません。

直接保存には安全なコンテキスト、`showOpenFilePicker()` とファイル書込API、および利用者の権限許可が必要です。ボタンはAPIの実際の有無で切り替えます。HTTPSやlocalhostも選択肢ですが、通信やサーバーを利用の必須条件にはしていません。`file://` の扱い・権限はブラウザによるため、利用する環境で確認してください。非対応・拒否時にも従来のローカル読込・編集・ダウンロードを利用できます。次回起動時のハンドル・権限復元は行いません。

比較と保存確定を一体で行うAPIはありません。確定直前にも再比較し、対応する実装では排他的な書込ストリームを要求しますが、外部エディターや同期ソフトによる最終比較後の同時変更を完全には排除できません。保存操作中は他のアプリで同じファイルを書き換えないでください。

自動ブラウザ試験はLinux Chromium 153で、GUI・ダウンロード・オフライン動作、模擬ハンドルによる成功・競合・失敗、ネイティブ読込と権限拒否時の保護を確認しました。その後、利用者から実機での直接保存・再読込と外部変更時の警告・保存停止の成功報告を受け、第5段階を完了としました。利用者のOS・ブラウザ名／版数は未提示で、各OS・各ブラウザでの網羅確認ではありません。競合後のファイル内容の手動照合など、個別の実機結果が未提示の項目もTESTINGに区別して記録しています。

参照: [ファイル選択API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showOpenFilePicker)、[書込ストリーム](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)、[権限要求](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/requestPermission)。

リポジトリのソースから作成する場合:

```sh
npm ci
npm run build:web
```

生成された `dist/web/index.html` を開いてください。`web/index.html` はビルド用テンプレートです。esbuildは開発時だけ使用します。実際の共通コア、`jsonc-parser`、共有UIとGUIエディターをまとめ、VS Codeアダプターは含めません。既存の拡張は `src/` と `media/` に維持しています。依存の版数は第3段階から変更していません。

配布物にはプロジェクトと `jsonc-parser` のMITライセンス、サンプルJSONCを同梱します。検証環境と未確認事項はリポジトリの `TESTING.md` を参照してください。
