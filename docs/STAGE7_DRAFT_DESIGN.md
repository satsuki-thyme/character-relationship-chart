# 第7段階：ローカル下書き保存の採否用設計

2026-10-04 JST。**設計のみ。常時永続化は未実装・未承認。** Undo/Redoは独立して実装・検証済み。設定や人物データを外部送信せず、ファイルハンドルの再起動後復元も追加しない。

## 今回の推奨と選択

現在のUndo/Redoは誤編集を戻せるが、再読込・終了・ブラウザ障害からは復旧できない。離脱警告が表示されるとは限らない。設定と表示を明示保存／ダウンロードする運用を基本にする。

| 選択 | 利点 | 残る制限 |
| --- | --- | --- |
| 当面採用しない（推奨） | 作品や未反映入力がブラウザに残らず、現行の保存方法を維持 | 再読込で未保存の変更・未反映入力・履歴を失う |
| 明示選択式の下書きを採用 | 有効にした作品の最後に記録できた内容を次回復元できる | 端末／ブラウザに機微データが残る。削除・容量不足・非対応時には復旧できない。実装と追加受入が必要 |

誤再読込や長時間編集での損失が利用上の課題なら後者を選ぶ。採用する場合も初期値OFF、作品を開くたびに明示的に有効化する。無条件の全作品保存、外部同期、元ファイルの自動保存は採用しない。以下は後者を承認されたときの最小実装案であり、現行機能の説明ではない。

## 記録範囲案

IndexedDBにアプリ専用のスキーマ版付き下書きを保存する。JSONCと表示の公開ファイル形式にはキーを追加しない。

| 項目 | 記録・復元方法 |
| --- | --- |
| 反映済みJSONC | BOM・改行・コメントを含む本文をそのまま保存。復元前に既存coreで検証 |
| 表示 | 既存version 1の正規化状態。人物ID・配置・カメラ・layout・uiを同じレコードに保存 |
| 未反映フォーム | 開いている種別、対象ID／インデックス、全入力値、フォームの基になる設定本文の指紋を別フィールドに保存。入力が不正でも文字として保持し、反映済み本文へ混ぜない |
| 識別 | ランダム下書きID、元ファイル名、利用者が付ける任意メモ、作成／最終記録日時、元の読込時のSHA-256とバイト長（得られた場合）。指紋不明は不明と記録。同名を同作品とみなさない |
| 保存基準／停止の説明 | 下書き作成時に未保存・競合停止だったことを案内用に保持する場合も、復元時の書込権限や保存済み判定の根拠にはしない |
| 保存しないもの | ハンドル・権限・絶対パス・Undo/Redo全履歴・検索語・選択対象・API資格情報 |

フォームの種別／対象と基になる設定が一致しない場合は入力を表示しても反映を止める。利用者が対象を確認し、転記または破棄を選ぶ。非同期応答待ちの操作を再送せず、最後に確定した本文と入力を区別する。複数タブは別下書きIDを使い、同じ名前のレコードを相互に上書きしない。

## 記録・復元・破棄

有効化時に保存範囲と端末に残ることを説明する。変更後約1秒の間引きで、本文・表示・フォームを一つのトランザクションとして記録する案とする。世代番号で古い非同期書込が新しい記録を置換しないよう直列化する。終了イベントだけに保存を依存しない。最終記録日時と記録失敗を画面に表示する。途中の未完了保存より新しい入力を回収できるとは表示しない。

次回起動は下書き一覧の通知だけにし、自動復元しない。ファイル名・任意メモ・日時・指紋を示し、現在の未保存内容があれば既存の破棄確認を行う。選んだ下書き全体を検証してから、**「下書きから復元・保存先未選択」** の新規セッションとして開く。Undo/Redoは空から始める。本文・表示は未保存扱い、未反映フォームは未反映のまま戻し、明示選択した元ファイルの現在内容を再読込するまで直接保存できない。下書きの指紋一致だけでハンドルや基準を採用しない。別作品・同名ファイルに自動結合しない。

「この下書きを削除」は対象名・日時を確認してから実行し、成功を確認するまで一覧から消さない。「この作品の下書き保存を停止」と「既存下書きも削除」を区別する。通常の明示保存やダウンロード完了だけで下書きを自動削除せず、必要な内容が残っていないか利用者が決める。元ファイルは削除しない。

## 機微データ・上限・失敗

端末の同じブラウザプロファイルを利用する人や、その保存先の管理者から読める可能性がある。暗号化された私的保管庫とは説明しない。共用端末ではOFFを推奨する。外部通信・アクセス解析・クラウド同期はアプリに追加しない。ブラウザ自身の管理や同期はアプリ外の条件として区別する。

案のアプリ上限は同一保存領域で3下書き、1件12MiB、合計24MiB（レコードをUTF-8 JSONとして数える）。既存coreの本文・表示・人物数等の上限はさらに適用する。フォームは1件合計200,000文字までとし、超過時は入力を切り詰めず記録を止めて通知する。ブラウザの割当て容量を保証値にしない。上限・QuotaExceeded・権限拒否・利用不可・破損時は、現在の図と入力、前回成功した下書きを保持し、再試行／既存下書きの明示削除／ファイルへの退避を案内する。古い下書きの無断削除や部分復元はしない。

ブラウザの保存はoriginやプロファイルに依存し、利用者によるサイトデータ削除・容量制限等で失われ得る。`file://`、プライベートモード、別の公開先では同じ領域を使えるとは保証しない。非対応ならメモリー編集と明示ダウンロードを維持する。永続ストレージ権限の自動要求は行わない。

根拠: [WHATWG Storage Standard](https://storage.spec.whatwg.org/)（origin・保存の許可／容量／削除）。上限・間引き時間・復元の扱いは本プロジェクトの設計提案で、ブラウザ仕様の保証ではない。

## 承認後の検証条件

OFFで書込ゼロ、有効化範囲だけ記録、全フィールドと未反映フォームの復元、明示破棄、同名別作品・複数タブ分離、再読込後の保存先未選択、容量不足／利用拒否／破損時の保持、遅延応答・ページ終了、通信ゼロ、現行Undo/Redo・競合停止・VS Code回帰を検証する。採用時はこの第7段階内で実装・配布・利用者確認まで完了する。第8段階へ黙って持ち越さない。
