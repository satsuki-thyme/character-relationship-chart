# 第7段階の実行用プロンプト

開始条件: 第6段階の表示データ保存・再読込・外部変更時の停止／内容保持を実機報告と自動試験で照合し、完了判定が記録されていること。実装・自動検証済みだけの段階では開始しない。対象ソースと第6段階配布物の一致・Dropbox既存ソースへの反映は別に確認する。第5段階の完了済み報告を過去の確認待ちと混同しない。

推奨: 高性能モデル／高推論モード。設定・表示の履歴、保存先と保存済み基準、未反映入力、競合停止状態の整合を同時に扱うため。

---

`Dropbox\www\studio\character-relationship-chart\` の第7段階「Web編集中の取り消し・復旧性を高める」を実装・検証してください。

最初に最新版IDAD、プロジェクト指示、`.git` と現在の未コミット差分、README、MGMT、工程表、設計・開発・データ仕様、TESTING、第6段階変更明細と `docs/STAGE6_ACCEPTANCE.md` を読み、第6段階の完了判定・ソース反映・配布物の一致を確認してください。第6段階が未完了なら、その確認・安全な反映を先に完了し、第7段階の実装を始めないでください。ユーザーの変更を保護し、バックアップ作成・commit/push・公開は行わないでください。

目的は、ページ内の主要GUI反映を安全にUndo/Redoできるようにすることです。既存coreのJSONC編集と共有UIを使い、工程表の第7段階に沿う最小構成を実装してください。

- まず履歴対象と操作単位を明確にする。設定本文、人物ID変更・削除に伴う配置参照、図とフォームの状態を整合させ、未反映入力を暗黙に適用・破棄しない。
- Webホストの履歴はメモリー内から実装する。Undo/Redoで設定／表示を過去状態へ戻しても、明示選択したファイルハンドル、生バイト基準、確認済み保存スナップショット、競合・結果不明の停止状態を巻き戻さない。保存済み基準との比較で未保存状態を判定する。
- 新しい編集、設定切替、表示だけの再読込、人物ID変更、保存中のUndo/Redo、古い非同期応答と履歴の対応を検証する。別作品の履歴・配置を混ぜない。
- 保存は明示操作だけとし、Undo/Redoが実ファイルを書き換えない。設定と表示の別保存、ダウンロードで退避、競合・失敗時の図・入力保持を維持する。
- ページ再読込に備えたローカル下書き保存は必要性と保存範囲・復元／破棄・機微データ・元ファイルとの識別・上限・失敗時の扱いを整理して設計する。常時永続化の採用は利用者の選択を確認してから実装する。承認待ちでもUndo/Redoの実装・検証とレビュー可能な設計は完成させる。外部通信・ハンドルの再起動後復元は追加しない。

`.jsonc` / `.view.json` 形式、IDと表示名、複数所属・関係参照・描画、JSONCコメント保持、coreの環境非依存、VS Code保存・Undo・競合保護、名称・識別子・0.1.0、本番依存、人物データの外部送信なしを維持してください。新しい本番依存が必要なら導入前に影響を整理してください。ブラウザAPIに原子的な比較付き保存がない制限は引き続き明示してください。

Web SVG、本格ディレクトリ再編、assignment、英語化、commit/push、公開・デプロイは対象外です。第8段階に着手しないでください。

少なくとも `npm run check`、`npm test`、`npm run test:web`、共有UI／Web DOM、関連実ブラウザ試験、`npm run build:web`、`npm run package` を実行してください。コメント・ID参照・複数所属・配置・未保存判定・保存済み基準・競合停止・フォーム保持のUndo/Redo往復と、新しい編集でRedoが破棄されることを検証してください。オフライン、通常操作のHTTP(S)送信なし、VS Code回帰を確認し、模擬APIとネイティブAPI・実機の結果を区別してください。

第7段階名のWeb ZIPとVSIXを生成し、検証済みソースと照合してください。README、Web README、設計・開発・データ仕様、TESTING、MGMT、工程表、change-detailsを実績に合わせて更新し、過去記録を保持してください。直接反映できない場合は元ファイルを保全し、取得時差分とSHA-256を守る反映用成果物を提示してください。
